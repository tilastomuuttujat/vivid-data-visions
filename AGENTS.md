## Atlas architecture
- Keep atlas data in a separate JSON file and validate user imports before replacing in-memory data, so both views share the same qualitative source without persistence.
- Share the atlas interface between the TanStack preview and standalone HTML exports, so the downloadable versions retain the same interactions.
- Use SVG for the 2D graph and React Three Fiber for the client-only 3D graph; positions encode theme grouping rather than indicator values.

- Observatorio view derives star roles from atlas stage numbers and wave definitions in-component; brightness encodes systemic role, never measured values (indicators are excluded).
- Planeetta view shares one layout model (planet-model.ts) between the SVG semantic-zoom map and the R3F globe; zoom distance selects the information level, plates/clusters are interpretive groupings.

- Standalone download (scripts/standalone) bundles the real app components into one HTML with hash routing, while atlas/anchors/maakunnat JSON stay external and load at runtime — so the download matches the preview and data stays editable.
- GitHub Pages deploy (.github/workflows/deploy.yml) builds scripts/standalone and serves index.html + data/*.json, because Pages cannot run the SSR app.
- Admin editing (src/lib/editor) mutates the imported JSON objects in place and publishes changed files to src/data via one Git Data API commit with baseline checks and a non-forced ref update with a token kept only in the admin's sessionStorage — no backend needed, and the push triggers the Pages workflow.
- Murrokset view (src/components/murrokset) links decisions to the 10-period metanarrative by year; src/data/lainsaadanto.json is regenerated from the user's Excel with scripts/data/convert-lainsaadanto.py, so the spreadsheet stays the editable source.
- DecisionNetwork uses a pinned TTT relation snapshot and explicit decision mappings; preserve source direction, distinguish exact counterparts from context, and never infer missing edges or treat source confidence as validated effect evidence. See src/components/murrokset/NETWORK.md for refresh and verification.

- Legislation decision IDs are permanent spreadsheet keys, never row numbers. Use the importer migration before changing legacy workbook titles; unknown assessment labels fail closed.
- Standalone release downloads are generated by scripts/package-site.py from the same build as Pages; preserve relative base paths and archive data files. ThemeGroup mounts closed analyses on first opening while keeping deep links functional.
- Ankkurit view (src/components/murrokset/ankkurit-model.ts) groups TTT cards into seven editorial anchors; inter-anchor arcs come only from recorded source edges in source direction, so grouping never invents causality.
- Murrosmaisema condenses the source-directed systemic timeline: seven editorial anchors have separate chronological rows on one shared time scale. Dashed milestone guides mark the beginning of existing turning-point periods; they never create causal relations. Preserve source direction and explicit decision mappings.
- Kehityskaari view (src/components/kaari) shows three editorial force lines and seven turning points; line heights are interpretations, and the optional deep panel reads only the exported murrosmatriisi evidence JSON (no live Supabase calls).
- Teemavertailu (src/components/teemavertailu) draws each atlas theme as a six-stage arc from teema-model.ts; heights encode the stage, not measured values. Kehityskaari sub-streams (SUBLINES) are editorial readings under the three forces.
